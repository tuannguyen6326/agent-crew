agent-crew

A thread per task. A fleet that ships.

What it is

A fleet of chiefs, disposable workers, everything on disk.

agent-crew is an agent distro: a directory of instructions (AGENTS.md), skills, and bash tooling that turns a terminal coding agent (Claude Code first) into a fleet orchestrator — no app, no build step, the checkout is the product. The crewchief never edits projects itself: every task goes to a crewmate in its own worktree and window, and finished work lands as a reviewed PR, an approved local merge, or a report.

Architecture

No daemon, no sockets. Disk and panes are the only channels — a restart is a non-event.

ac-send.sh
one verified literal line into the crewmate's pane
state/<id>.status
append-only event log the crewmate writes (done:, blocked:, needs-decision:…)
state/<id>.meta
key=value task record (window, worktree, harness, mode…), last write wins

Each contract has one authoritative file: the script's header comment is its spec, and tests/*.test.sh are executable behavior specs.

Task lifecycle

From order to teardown — the order is the contract.

Flow is picked per order at intake: the captain's words → a config/flow pin → the crewchief's own receipted triage. Review is derived (always for staged & crew-ship); QA gates the merge, never the push. Full law: AGENTS.md §5.

One task, birth to teardown

ac-brief.sh→ ac-spawn.sh→ ac-watch.sh→ ac-wake-drain.sh→ land→ ac-teardown.sh
  1. ac-brief.sh <id> <project>scaffold the brief — the brief is the crewmate's whole contract.
  2. ac-spawn.sh <id> <project>lease a pooled worktree inside the repo, open a herdr tab, launch the harness.
  3. ac-watch.shone armed watcher covers the fleet; it wakes only on actionable events.
  4. ac-wake-drain.shon wake: drain, peek, steer with ac-send.sh, or escalate to the captain.
  5. landPR merge (crew-ship / direct-pr) or local fast-forward; learnings + backlog update happen at landing, automatically.
  6. ac-teardown.sh <id>fail-closed — refuses to destroy unlanded work; the worktree returns to the pool.

Governance

Every decision made on the captain's behalf reaches them as a receipt they can veto — never as silence.

Receipts — TRIAGE:, SELF-APPROVED:, GATE-LOOPED: — go to the chat and the family room. The merge gate is always the captain's, and +yolo never waives it. Full law: AGENTS.md §5.

Rooms & roomchiefs

Chat is the transport; rooms are the record. One family = one backlog line = one room.

room
data/<family>/room.md — append-only ledger of gates (GATE:), asks (ASK:), receipts, and answers (DECIDED:); ac-room.sh list is the captain's inbox
promotion
default always — a thread per task: every family gets its own roomchief thread at intake (capped by config/room-parallel); auto/never pins opt a fleet out
routing
anything about a promoted family is routed to its roomchief, never worked by the fleet chief — and never focus-stolen without consent
handback
a roomchief ends by reporting back (HANDBACK: + a durable wake); the fleet chief demotes it and closes the room, fail-closed

In-repo worktree pool

Pooled, reusable worktrees that live inside the project itself.

<project>/.crew/
  worktrees/<n>/     # detached-HEAD worktree slots (the crewmate's cwd)
  slots/<n>.meta     # per-slot lease state (key=value)
  lock/              # mkdir lock with stale-owner recovery
  config             # optional: max_trees=8

Returning never deletes — dependency and build caches survive between crewmates. Dirty slots are never silently reset, dead-owner leases self-heal, and prune only removes clean slots verified merged against the live remote. Crewmates work on crew/<id> branches.

crew-ship pipeline

Eight hold-and-fix steps, executed agent-side with durable state in <repo>/.crew/ship/.

intent→ rebase→ review→ test→ document→ lint→ push→ pr

Findings model: every judgment step emits findings with a severity (error / warning / info) and an action — fix (a crewmate fixes; the reviewer never does), ask-user (parked for the captain with options and a recommendation), or no-op. A failing step holds the run — it never restarts from intent — and a code-changing fix re-opens completed test/lint. Review is one fresh pane agent on the exact immutable ref (ac-verify codereview); a ref-changing fix starts a fresh round over the previous reviewed ref-to-current ref delta while rechecking the previous round's open findings. push is force-with-lease anchored to the exact inspected remote SHA. The agent stops at checks-passed — merging stays with the captain.

crew-qa pipeline

Standalone behavioral proof — does the delivered change actually work?

bin/ac-qa.sh drives the booted deliverable from outside: api / db / workflow cases, web cases in a real browser, a final assembled-flow case, per-case evidence with screenshots, and a machine-readable verdict. It never fixes anything and never runs a unit suite — behavioral proof after delivery, separate from code review.

boundary
evidence comes only from client-facing / API / integration / E2E / database boundaries of the booted system (captain ruling 2026-07-25)
execution
exactly one fresh independent QA pane per profile round — never the implementing crewmate; inputs frozen (config, scope, store, exact refs) before start
infra
task-scoped docker compose, no fixed host ports; ambient secrets never reach the service under test
verdict
durable run.meta owns it; the completion gate refuses passed until every step, receipt, and visual checks out
merge gate
qa.require_for_ship: merge helpers refuse a head with no passing attestation — QA gates the merge, never the push

Order it with the --qa pin, or by triage: user-facing, DB, financial, or captain-critical changes.

Session backends

One primitive surface — window new / alive / send / capture / kill. The backend is pinned per task, so a config flip never strands a running crewmate.

the only backend

herdr

One tab per crewmate. Three self-healing window groups per fleet: <fleet> (crewchief) for chiefs and deputies, <fleet> (crewmate) for work tabs, <fleet> (pane-agent) for verification agents — so the captain always tells who is who. ac-relocate.sh moves a live window between groups without losing its session.

Delivery modes

Picked per task at intake and pinned on the backlog row — never a registry property.

ModeWhat the crewmate doesHow it lands
crew-shipRuns the built-in 8-step pipeline (time-expensive — needs the captain's word)PR → captain approves → ac-pr-merge.sh
direct-prPushes crew/<id> and opens a PR, no pipelinePR → captain approves → merge
local-onlyLeaves work merge-ready on crew/<id>, never pushesac-merge-local.sh fast-forward after approval

Mode is per-task, never a registry default — a backlog-row pin is the captain's recorded word; unpinned, the chief picks cheap modes autonomously and must ask (with the reason) before crew-ship, staged, review, or QA. +yolo stays per-project and lets the crewchief self-approve routine reversible calls; destructive actions and merges always need the captain.

Supervision

The watcher spends bash, not tokens — and completion is push-first.

Every wake is published durably first (state/.wake-spool[.<family>]/, one record per file) — a crash loses nothing. A Stop hook blocks any turn that would leave crew in flight unwatched; the one captain notification (config/wedge-alarm) fires only when the fleet is blocked by the captain.

WakeMeaning
push:<id>the agent announced its own completion (ac-done.sh) — the fast path, milliseconds
report:<id>a captain-relevant line appeared (done: / blocked: / needs-decision: / failed:)
ask:<id>blocked on an interactive prompt — answer or steer at once
ended:<id>the pane ended its turn with no marker — it is waiting on you; read it
stale:<id>quiet while still working — the soft signal
gone:<id>the window vanished — the backend answered and does not know that pane
unobservable:<id>the backend itself could not be read — fix the backend, never tear the crew down
heartbeatnothing actionable — re-arm and move on

Home & state

The operational home is wherever AC_HOME points; there is no fallback - unset is refused.

$AC_HOME/                    # one fleet in the container, e.g. ~/Work/ac-homes/lab
  config/                    # local knobs: backend, crew-harness, launch-<harness>…
  records/
    projects.md              # project registry with delivery modes
    backlog.md               # In flight / Queued / Done
  data/
    <id>/brief.md            # direct task: flat brief (report.md for scouts)
    <family>/<stage>/        # staged flow: design/ (or spec/ arch/ plan/) implement/ qa/
    <family>/room.md         # family root: room + gate artifacts
  projects/<name>/           # clones; READ-ONLY for the crewchief
  crewdomains/<name>/        # crewdomain package: records/{backlog,projects}.md, CREWMATE.md, projects/ symlinks
  state/
    <id>.meta  <id>.status   # task record + event log
    .wake-spool[.<family>]/    # durable wakes, one record per file, one spool per consumer scope
    .pane-<id>                # herdr pane handles
    archive/<id>/            # post-teardown state

All persistent truth lives on disk — a restart is a non-event. Crewdeputies get their own nested home under crewdeputies/<name>/ (own clones, own budget); crewdomains stay inside this fleet as durable packages (ac-domain.sh, registry records/crewdomains.md) — pick a deputy for isolation, a domain for a knowledge and backlog slice over the fleet's own clones.

Skills

/crew-ship

Validate committed changes through the 8-step pipeline before they reach the push target.

/crew-qa

Drive the qa pipeline (bin/ac-qa.sh): dockerized infra, per-case evidence, machine verdict — standalone, separate from code-review; never fixes.

/document

Doc-authoring method at delivery: judge whether docs are warranted, create missing ones in the project's conventions, sync every doc the change makes stale.

/order-direct

Captain pin: start an intake with flow pinned to direct; optional --mode / --promote / --qa pins, the rest of the arguments is the order verbatim.

/order-staged

Captain pin: start an intake with flow pinned to staged (design → execution); review is required and execution owns IMPLEMENT + DELIVERY.

/epic-intake

Decompose a multi-deliverable order into a gated story map with a dependency DAG, push-scheduled via ac-ready.sh.

/gate-review

Build the one consolidated pre-implement review page for a captain-required gate — a single HTML file reviewed in rich-review.

/bearings

Captain-facing status report of the whole fleet — crew in flight, backlog, blockers, PRs.

/rich-review

Open an HTML artifact in the dashboard's native review loop for human annotation and feedback.

/domain-knowledge

One idempotent onboard-and-update flow for a crewdomain's whole knowledge surface — gated on ac-domain.sh validate.

/debrief

Manual reset-time catch-all: route and curate uncaptured knowledge, reconcile rooms and fleet state fail-closed, return a durable resume pointer. Landing-time debriefs remain automatic.
